## Goal
Add PostgreSQL versions of four modules as **new, unused modules under `src/pg/`**, next to the untouched SQLite originals. ## Design rules
1. **Same names, same return shapes, same error `status`/messages.** Each function becomes `async` and takes an executor `q` (a `pg` Pool *or* a transaction client — anything with `.query`) instead of `db`. The Slice 5 conversion of `server.js` must be mechanical: add `await`, swap the first argument.
2. **Import pure helpers, don't copy them.** `src/catalog.js`, `src/requests.js`, `src/assignments.js`, `src/serial.js`, `src/timeRange.js` have no DB imports, so `src/pg/*` may `require` their pure exports (`normName`, `nameKey`, `normKeywords`, `SEP`, `MAX_NAME`, `TRANSITIONS`, `TERMINAL`, `LIVE`, `OPENED_MSG`, `canTransition`, `ASSIGNMENT_TYPES`, `TYPE_LABEL`, `returnBy`, `capacity`, `normalizeType`, `T.*`). Do **not** `require('../db')` (it opens SQLite and creates `data/` at import time). Do not share the SQLite catalog's module-level cache. Note in the report that these helpers move at cutover.
3. **Settings defaults** (`DEFAULT_SETTINGS`) live in `db.js` and cannot be imported. Duplicate them in `src/pg/settings.js` and add a parity test that loads `src/db.js` under a temp `DATA_DIR` (as existing tests do) and asserts `getSettings()` equals the PG result on a fresh database.
4. **Timestamps (D-46: TEXT stays TEXT).** `src/pg/time.js` exports the SQL expressions/helpers for `YYYY-MM-DD HH:MM:SS` **UTC, second precision, truncated** (SQLite `datetime('now')`) and `YYYY-MM-DD` (`date('now')`). Use `clock_timestamp()` (statement-time like SQLite), not `now()` (transaction start). A test asserts both formats by regex and that string comparison against stored values (`hold_expires_at > now`) behaves as in SQLite. Confirm the baseline's column defaults produce the same format when an INSERT omits the column, and report if not.
5. **Case-insensitivity.** The baseline already has `lower()` unique indexes (`assets_tag_lower_key`, `accounts_login_email_lower_key`, `idx_employees_work_email`) under the "C" collation (ASCII-only folding, same as NOCASE). In this slice's modules the case rules are: catalog sibling names (`name_key`, JS `nameKey`) and `ORDER BY name_key`. Preserve them. Also add a small test that fixes the **lookup idiom for Slice 5**: `WHERE lower(tag) = lower($1)` / `lower(login_email) = lower($1)` / `lower(work_email) = lower($1)` match case variants and the unique indexes reject case-variant inserts. Search keeps ASCII-insensitive matching (SQLite `LIKE` → `ILIKE` or `lower()` both sides) wherever a converted function does text matching (catalog search is in JS and needs nothing).
6. **Locking.** `createAssignment` opens its own `withTransaction` (mirrors `db.transaction().immediate()`; nested transactions are rejected by the helper) and calls `lockAsset` **first**, before reading employees, reservations, waitlist holds or assignments (Slice 2 lock-ordering rule). It then runs the exact same checks in the same order (archived/status, `available_to_request`, confirmed-reservation guard, waitlist-hold guard with "hold owner's own checkout accepts the offer", pending waitlist-born reservation guard, duplicate holder, seat capacity), inserts with `RETURNING`, closes the owner's holds, refreshes status, writes `activity`, and returns `{ assignment, asset, employee }`. `refreshStatus` takes `q` (callers pass the transaction client). `lastInsertRowid` → `RETURNING id`; `.changes` → `rowCount`; `?` → `$n`.
7. **`requests.transition` stays a compare-and-set** (`UPDATE … WHERE id = $ AND status = $ [AND opened_at IS NULL]`), no row lock needed; under READ COMMITTED a loser sees 0 rows and gets the same 400 messages. Keep `completeEquipmentRequests`/`completeReturnRequests` semantics (they accept a client or pool).
8. **Catalog cache.** Keep the read-all-then-cache design, keyed on the pool (not a db handle). Invalidate **after** a write has committed: a write on a bare pool invalidates after the statement; a write on a transaction client must not repopulate the cache from uncommitted state. Use a generation counter so a load that raced with an invalidation is not stored. Sibling-name uniqueness is check-then-insert: verify what unique index the baseline has on `(COALESCE(parent_id,0), name_key)`, and map a `23505` unique violation to the same 400 message as `assertSiblingFree` so a race returns the same error.
9. **Pool pressure.** A `createAssignment` waiting on a held asset lock occupies a pool connection (max 10). Keep the concurrency tests within the pool size and **document in the report** the pool-size implication for Slice 5 (do not change pool config).

## Required PostgreSQL test coverage ("equivalent behavior" — port the scenarios of the existing SQLite tests for these modules, `test/catalog.test.js`, `test/requests.test.js`, `test/request-integrity.test.js`, `test/lifecycle.test.js`, `test/assignments.test.js`, `test/serial.test.js` as relevant, using the module-level API instead of HTTP)
- **Settings:** fresh-database defaults equal SQLite's; `setSetting` upsert for string and JSON values; `getSettings` typing (numbers, boolean `overdue_reminders`, parsed lists).
- **Catalog:** sibling-name uniqueness ignoring case/whitespace incl. archived siblings; cycle refusal on move; archived ancestor makes a subtree non-live; restore requires live parent; `usage`/`deleteNode` refusal; rename/move returns `{oldPath,newPath,wasRoot,isRoot}`; search text and inherited keywords; `findLiveByPath` with `>` and `›`; keyword normalization limits; cache invalidation after write, and no stale cache after a rolled-back transaction.
- **Requests:** every allowed and refused transition per type; terminal states; `opened_at` set once and only by admin action/`openRequest`; rescind-until-opened incl. `requireUnopened`; **concurrent approve vs cancel: exactly one wins and the loser gets the "just updated" 400**; `lifecycle` incl. `rescinded` vs `cancelled`; `completeEquipmentRequests` permanent-vs-temporary rule and NULL type; `completeReturnRequests`.
- **Assignments:** validation order and messages (permanent needs admin, checkout needs a valid return date/time, archived/status, not-in-pool 404 for non-admin); confirmed-reservation guard time-aware (noon return vs 1 PM pickup passes; overlap is 409; own reservation doesn't block); waitlist-hold guard (other's hold blocks only its interval; owner's checkout closes the hold with the `waitlist_checked_out` activity row); pending waitlist-born reservation guard; duplicate holder; status/`condition` updates and `activity` text.
- **Concurrency (must pass reliably, run it repeatedly while building):** (a) a multi-seat asset (`license_seats = 3`) with ≥8 simultaneous `createAssignment` calls for different employees → **exactly 3 succeed, the rest fail with "All license seats are in use.", the active-assignment count never exceeds seats, asset ends `checked_out`**; (b) single-seat asset, 2 simultaneous callers → exactly one wins; (c) same employee twice at once → one wins, "already has this asset"; (d) a failure mid-transaction (e.g. a nonexistent `actorAccountId` FK) rolls back the whole assignment, activity row and status change; (e) assignments on two different assets proceed independently (no cross-asset blocking).
- **Time/case:** format and comparison tests (Design rule 4); lookup-idiom tests (Design rule 5).

- `npm test` (no Docker): all **548** existing tests pass, PG suites skipped with a message. With `npm run db:up`: existing 548 + all new PG tests pass; `npm run test:pg` runs only PG tests and fails if PG is unavailable.
- Concurrent assignments never exceed license seats (criteria above), with no deadlocks and no leaked clients (pool `idleCount`/`waitingCount` returns to baseline after the tests).
- No diff in the no-touch list; no `package.json` change beyond what is strictly needed (expect none); Railway/staging/Dockerfile/env untouched; no remote connection made.
- `src/pg/*` imports nothing from `src/db.js` and never opens SQLite.
- Behavior equivalence: same function names, return shapes, error statuses and messages as the SQLite modules for every ported scenario.
